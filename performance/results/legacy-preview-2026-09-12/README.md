# Maximum legacy-preview allocation comparison

The actual legacy loader from audit baseline `fe9556cf9f011297e16500f18cdf04b991b35635` and the current loader each processed a 100 MiB fixture through genuine Response, ReadableStream and Blob objects. Three samples per implementation ran in fresh Node processes, with alternating order. Every output matched the complete generated source SHA-256.

| Measurement | Baseline | Current |
|---|---:|---:|
| Explicit `Uint8Array.from` copies | 100 MiB in 100 calls | 0 bytes, 0 calls |
| Median sampled ArrayBuffer peak | 209,861,977 bytes | 209,861,977 bytes |
| Median sampled RSS peak | 266,223,616 bytes | 265,879,552 bytes |
| Median measured duration | 94.248 ms | 84.899 ms |

The measured improvement is the removal of one complete 100 MiB application copy. The sampled memory peak did not materially change: constructing the complete Blob still requires native storage. The instrumentation does not claim to account for native Blob, response, decoder or allocator copies.

The timed interval also includes generated stream chunks, expected SHA-256 calculation and instrumentation. These six local samples do not isolate loader CPU cost or establish a statistical speed improvement. Complete output SHA-256 verification happens after timing. Memory is sampled at stream production, explicit copies, progress callbacks and completion; it is not an exact instantaneous peak or browser heap measurement.

A PNG filename selects the full media-preview budget. The generated bytes are a transport fixture rather than a decodable image, so image rendering and paint are outside this measurement. Full-read EOF does not call the underlying stream cancellation hook; the separate loader tests verify cancellation behavior. The 256 MiB V8 heap option is not a physical-memory cap.

The [raw result](summary.json) records every sample, source and harness hashes, runtime, limits and content verification. Reproduce with `node performance/profile-legacy-preview.mjs` from the repository root. The audited baseline is pinned so later commits do not change the comparison.

`frontend_transfers/previews` independently reviewed the harness and validated the six saved samples and all three provenance hashes. No actionable findings remained after pinning the baseline and documenting the timed fixture work.
